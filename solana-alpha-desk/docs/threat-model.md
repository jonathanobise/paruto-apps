# Threat model

**Assets**: integrity of paper results and audit trail; owner account; provider credentials; the
guarantee that nothing can trade real funds. **Not in scope**: real funds (there are none).

| Threat                                     | Mitigation                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Someone uses the system to move real money | No signer, keypair, `sendTransaction` or swap-transaction endpoint exists; ESLint `no-restricted-syntax` forbids them; `tests/security/no-live-trading.test.ts` scans all source; there is no live runtime mode.                                                                                                                                                                                |
| Account takeover                           | Owner created only with a one-time `SETUP_TOKEN` secret; PBKDF2-SHA256 (100k iterations, the Workers maximum) passwords ≥ 12 chars; TOTP MFA required for admin actions in production; 5 logins/min per IP; lockout after 10 failures; generic error messages.                                                                                                                                  |
| Session theft / CSRF                       | 256-bit random session tokens, stored only as SHA-256; `HttpOnly; Secure; SameSite=Strict` cookie; 12 h absolute / 2 h idle expiry; logout revokes; mutations require the per-session CSRF token header and a same-origin `Origin`.                                                                                                                                                             |
| Abuse of the monitor bridge                | `/internal/v1/sql` requires an HMAC-SHA256 signature over timestamp, nonce and body with a ≥ 32-char secret; ±30 s skew; nonces stored and single-use; disabled when no secret is set; unreachable with a browser session. The bridge executes arbitrary SQL by design, so `BRIDGE_SECRET` is equivalent to database access: store it only as a Worker secret and in the monitor's environment. |
| Tampering with history                     | Audit events, handoffs, fills, ledger, stop events, rule results, breaker events and configuration changes are append-only via `RAISE(ABORT)` triggers; positions and orders cannot be deleted; closed positions are final; each audit row carries a SHA-256 checksum verifiable with `verifyAudit`. Corrections are new rows.                                                                  |
| Double execution / races                   | Single-use authorizations (trigger + unique order binding), guarded state transitions, idempotency keys, portfolio optimistic locking; tested with concurrent and duplicate deliveries.                                                                                                                                                                                                         |
| Bad or malicious provider data             | Zod validation of every response; on-chain facts preferred; discrepancy rule F014; freshness rule F015; fail closed on missing data; provider safety scores never decisive.                                                                                                                                                                                                                     |
| Prompt injection through token metadata    | Token names, descriptions, websites and socials are never passed to a model as instructions and never drive a decision; the optional AI adapter only summarises computed numbers, with untrusted strings quoted as data.                                                                                                                                                                        |
| Secrets exposure                           | Secrets live in Worker secrets / the monitor's environment; nothing is bundled into the static dashboard; API keys are stripped from stored evidence endpoints. `.env`, `.dev.vars` and `data/` are git-ignored.                                                                                                                                                                                |
| Denial of service / cost                   | Per-session API rate limit; Cloudflare in front; provider pacing and circuit breakers; API_BUDGET breaker; replay periods capped at 90 days.                                                                                                                                                                                                                                                    |
| Dependency compromise                      | Pinned versions with a lockfile; `pnpm audit` in CI; minimal dependencies (zod, decimal.js, hono, next/react, lightweight-charts, TanStack Query).                                                                                                                                                                                                                                              |

Residual risks: the public Solana RPC is unreliable from shared IPs; the Helius adapter has not run
against the live API; a compromised `BRIDGE_SECRET` grants database access.
